# End-to-end acceptance audit — 2026-11-14

Audit of the four-phase plan against the tree at `cb2b5bb`. The gate was green
(280 Rust tests, clippy clean, npm 14/14, browser E2E, idle 0/0, portable
replay) and all five new oracles passed. **The gate being green did not mean
the work was finished.**

## Verdict: NOT complete. Do not merge yet.

---

## A. BLOCKER — WP 1.7 is an inert library

`crates/odd-contracts/src/chief_ai.rs` is correct and well tested, but
**nothing in production ever calls it**. Every entry point is test-only:

```
cap_score        → called only from tests/delegation.rs
chief_ai::apply  → called only from tests
hardware_mass    → called only from tests
```

Consequences, each checked against the acceptance criteria:

| Requirement | Actual state |
|---|---|
| Per-stack `[AUTO-DELEGATED]/[MANUAL]` toggle in vehicle assembly | **Absent.** No UI, no wasm setter. |
| Delegated = +35 % mass | **Never applied.** `Contract::vehicle` ignores delegation; the flown mass is unchanged. |
| Delegated = +30 % cost | **Never applied.** No cost is surfaced anywhere. |
| Visible badge naming the chief and the kg | **Absent.** `badge` is built but never rendered. |
| Seff capped at 0.65 | **Never applied to a real score.** `score()` has no mask parameter. |
| Bitmask in the signed FDR | Present and signed — but **always 0**. |

`crates/odd-view/src/mission_bridge.rs` hardcodes
`delegation: DelegationMask::MANUAL` at both Settings constructors (lines 113,
203) and there is no setter, so the mask can never become non-zero in a real
flight.

**Why the oracle passed anyway:** `oracle_delegation_efficiency_cap` calls
`chief_ai::cap_score` directly. It proves the arithmetic, not that the game
uses it. This is the exact failure mode the project's own laws warn about —
a test that agrees with itself.

## B. Cryo is not a design lever

The card asks for "active cryo as a design lever". `thermal_design` is
hardcoded to `ThermalDesign::baseline()` at both Settings constructors, with
no setter and no UI. The player cannot add MLI layers or fit a cryocooler, so
the lever does not exist for them.

## C. Boil-off is invisible

`ThermalOutcome` is computed, signed and replay-verified, but never rendered:
the dossier has no thermal section and the debrief does not mention it. A
player loses 582 kg on the tug and is never told.

## D. "Scan at:" prints a placeholder, not a deployment URL

The card asks for `Scan at: <deployment URL + QR fragment>`. Both dossier
call sites in `fdr_bridge.rs` pass `fdr.verify_payload()`, which is a bare
`#verify=…` fragment, so the header prints
"this deployment, #verify= fragment (relative to the serving origin)".
The origin is never passed from JS.

## E. Minor — enum-order guard is still Rust-only

`propellant_wire_ids_are_frozen` guards the Rust enum. The duplicated JS
order in `web/engine-lab.js` and `web/mission.html` still has no assertion
tying it to Rust.
