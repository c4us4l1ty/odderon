# End-to-end acceptance audit — 2026-11-14

Audit of the four-phase plan against the tree at `cb2b5bb`. The gate was green
(280 Rust tests, clippy clean, npm 14/14, browser E2E, idle 0/0, portable
replay) and all five new oracles passed. **The gate being green did not mean
the work was finished.**

## Verdict at audit time: NOT complete. Do not merge yet.

**Remediation status: all five findings fixed, plus two exploits found while
fixing them. See "Remediation" at the end of this file for the closing
verdict and the evidence.** The findings below are kept as written at audit
time so the reasoning is not rewritten after the fact.

---

## A. BLOCKER — WP 1.7 is an inert library

`crates/odd-contracts/src/chief_ai.rs` is correct and well tested, but
**nothing in production ever calls it**. Every entry point is test-only:

```
cap_score        → called only from tests/delegation.rs
chief_ai::apply  → called only from tests
hardware_mass    → called only from tests
```

Consequences, each checked against the acceptance criteria:

| Requirement | Actual state |
|---|---|
| Per-stack `[AUTO-DELEGATED]/[MANUAL]` toggle in vehicle assembly | **Absent.** No UI, no wasm setter. |
| Delegated = +35 % mass | **Never applied.** `Contract::vehicle` ignores delegation; the flown mass is unchanged. |
| Delegated = +30 % cost | **Never applied.** No cost is surfaced anywhere. |
| Visible badge naming the chief and the kg | **Absent.** `badge` is built but never rendered. |
| Seff capped at 0.65 | **Never applied to a real score.** `score()` has no mask parameter. |
| Bitmask in the signed FDR | Present and signed — but **always 0**. |

`crates/odd-view/src/mission_bridge.rs` hardcodes
`delegation: DelegationMask::MANUAL` at both Settings constructors (lines 113,
203) and there is no setter, so the mask can never become non-zero in a real
flight.

**Why the oracle passed anyway:** `oracle_delegation_efficiency_cap` calls
`chief_ai::cap_score` directly. It proves the arithmetic, not that the game
uses it. This is the exact failure mode the project's own laws warn about —
a test that agrees with itself.

## B. Cryo is not a design lever

The card asks for "active cryo as a design lever". `thermal_design` is
hardcoded to `ThermalDesign::baseline()` at both Settings constructors, with
no setter and no UI. The player cannot add MLI layers or fit a cryocooler, so
the lever does not exist for them.

## C. Boil-off is invisible

`ThermalOutcome` is computed, signed and replay-verified, but never rendered:
the dossier has no thermal section and the debrief does not mention it. A
player loses 582 kg on the tug and is never told.

## D. "Scan at:" prints a placeholder, not a deployment URL

The card asks for `Scan at: <deployment URL + QR fragment>`. Both dossier
call sites in `fdr_bridge.rs` pass `fdr.verify_payload()`, which is a bare
`#verify=…` fragment, so the header prints
"this deployment, #verify= fragment (relative to the serving origin)".
The origin is never passed from JS.

## E. Minor — enum-order guard is still Rust-only

`propellant_wire_ids_are_frozen` guards the Rust enum. The duplicated JS
order in `web/engine-lab.js` and `web/mission.html` still has no assertion
tying it to Rust.

# Remediation — closing verdict

All five findings are fixed, and fixing them exposed **two further exploits**
that the original audit had not reached. Everything below is gated.

## A. WP 1.7 is now reachable from a real flight

* `Contract::vehicle_delegated(spec, mask, design)` charges the chief's margin
  to the **dry mass that flies**; `vehicle()` is the manual, baseline-design
  call, so every historical certificate keeps its exact mass bits.
* `score_delegated(...)` applies `cap_score`; `odd_verify::compute` passes the
  mask, and `spec_from_record` rebuilds it from the signed byte, so a
  delegated certificate cannot replay as manual and collect the uncapped
  score.
* The assembly panel (`web/assembly.js`, `#assembly`) has a checkbox per
  discipline, reads the margin, cost, dry/wet mass, efficiency ceiling and
  badges back from Rust, and never recomputes them in JavaScript.
* Measured in the browser, contract 101: manual **S 0.916684 / Seff 0.9892**
  vs four chiefs **S 0.831885 / Seff 0.6500**; tug dry mass
  **5200.017 → 5267.612 kg** (+67.595 kg), cost ×1.3000.
* Regression that would have caught the original blocker:
  `crates/odd-verify/tests/delegation_flown.rs` — a *flown* delegated mission
  must mass more and score less, and dropping the mask must change the score.

## B. The cryogenic design is a paid player lever

`mission_thermal_set/get` expose layers, emittance, strut leak, radiator,
cooler lift and array output. Two rules keep it honest:

* a cooler is refused without radiator area, and cryo edits are refused on a
  storable stage (which has no fit-out and says so in the panel);
* **hardware beyond the contract baseline is charged to dry mass** — blanket,
  radiator *and* the array that runs the compressor.

## C. Boil-off is visible where the player and the auditor look

* Debrief: a real boil-off row (measured kg, or an explicit storable zero),
  propellant boiled off, relief-valve openings, cooler electricity, and the
  number of delegated disciplines. The old "not modeled in this work
  package" disclaimer is gone.
* Dossier: **Annex C** prints the signed fit-out, per-tank and total loss,
  cooler MJ, every vent opening (time, tank, pressure, temperature) and the
  delegation provenance. Pre-v3 records say they carry no thermal claim;
  storable stages say zero is measured, not missing.

## D. "Scan at:" is an absolute, scannable URL

The page states its own origin (`mission_fdr_origin_*`); only `http(s)` URLs
without a query or fragment are accepted, bounded at 512 bytes. The QR now
carries `https://host/mission.html#verify=…`, which a phone camera can
resolve. Without an origin the dossier still labels the fragment as relative
rather than inventing a host.

## E. One propellant ordering, not four

`mission_propellant_count/label/band/wire_id` are read from
`odd_propulsion`; `web/engine-lab.js` builds the selector from them and no
longer restates `BANDS`/`LABELS`. The HTML `<option>` list is generated. The
browser gate asserts the selector values equal the signed wire ids, the
labels equal the solver labels, and the solver refuses a ratio just outside
each band it advertises.

## Two further exploits found while remediating

1. **Free cooling.** `Contract::vehicle` charged only engine + airframe, so a
   player could fit 400 m² of radiator and sixty blanket layers, zero the
   boil-off, and carry none of the kilograms. Now charged, and
   `certify_engine` recomputes the mass from the **signed** fit-out and mask:
   `oracle_cooling_cannot_be_claimed_without_its_mass` re-signs a record that
   claims 173.8 kg of cooling hardware at the light baseline mass and is
   refused at the mass gate. Thinning the blanket is genuinely lighter, so
   the trade-off runs both ways.
2. **Starved hydrogen.** The bus serves the oxidizer first; with the baseline
   3 kW array the compressor saturates it and the hydrogen tank gets nothing.
   Array output was not a player lever, so active cooling could never save
   the fuel. It is now a lever, and it is paid for: on the flown 6.94-day tug,
   **155.553 kg → 0.000 kg** boil-off for **+130 kg** of array, with the
   cooler draw rising to 3460.221 MJ. Both numbers are asserted in the gate.

## Gate after remediation

`./scripts/gate.sh` exit 0: **287 Rust tests**, clippy `-D warnings` clean,
npm 14/14, observatory E2E (including the absolute-QR assertion), the new
assembly E2E (45 checks), idle **0 callbacks / 0 worker messages**, and
native↔node↔chrome parity with portable replay.

Two intermittently failing tests were also fixed: the new origin tests
mutated the shared bridge statics without taking `bridge::test_lock()`,
which poisoned the mutexes for whatever ran next.

## Verdict: complete for the approved scope

WP 1.6, 1.7 and the v3 freeze are implemented, player-visible, signed,
replay-verified and gated. **WP 1.9 (server/leaderboard) remains deliberately
deferred** to the next session on this frozen schema, as agreed.

Non-blocking follow-ups, unchanged: re-tune the #102/#103 tank cards and the
Level-1/3 tolerances; `StageThermal::integrate` still sizes the fuel tank's
bus allowance from the oxidizer's end-state peak rather than its instantaneous
draw (the player can work around it with array mass, which is now a real
choice, but a shared instantaneous allocator would be better physics).
